# easyCode 创作关联项目 + git 分支 开发文档

> 版本：v0.4.0 ｜ 日期：2026-09-26
> 需求：新增创作时增加 git 地址或选择本地项目；git 地址自动 clone；按版本号创建/切换分支（已存在则切换）；支持选择用过的项目；markdown 文档落到项目的 `doc/` 下；润色时 Claude Code 切到项目目录执行。

## 1. 需求拆解

| # | 需求点 | 落地 |
| --- | --- | --- |
| R1 | 新增创作时可填 git 地址 | `CreateDialog` 里输入 git URL |
| R2 | 或选择本地项目 | 目录选择器（主进程 `dialog.showOpenDialog`） |
| R3 | git 地址自动下载 | `git clone` 到 `~/.easyCode/projects/<repo>` |
| R4 | 按版本号创建分支，已存在则切换 | `git checkout <branch>` 失败则 `git checkout -b <branch>` |
| R5 | 选择本地项目同样处理分支 | 同上 |
| R6 | 可选择已用过的项目 | 下拉列出 `projects` 表 |
| R7 | 文档放到项目 `doc/` 下 | 写 `<project>/doc/<标题>.md` |
| R8 | 润色时切到项目目录 | `spawn(claude, { cwd: projectPath })` |

### 已确认的三个决策

1. **分支名规则**：版本号 `1.0` → 分支 `v1.0`
2. **工作区不干净**：**拒绝并提示**，绝不自动 stash / 覆盖用户未提交的改动
3. **润色权限**：以项目目录为 cwd，但**仍禁掉全部工具**（`--tools ""`）。能读到项目的 `CLAUDE.md` 等上下文，但不会改任何文件

## 2. 数据模型

### 新表 `projects`

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | uuid |
| `name` | TEXT | 显示名（git 源取仓库名，本地取目录名） |
| `path` | TEXT | 本地绝对路径 |
| `source` | TEXT | `git` / `local` |
| `git_url` | TEXT NULL | git 源时的原始 URL |
| `created_at` / `last_used_at` | INTEGER | 时间戳 |

索引：`path` 唯一（同一路径不重复登记）。

### `creations` 新增三列（迁移）

| 列 | 默认 | 说明 |
| --- | --- | --- |
| `project_id` | NULL | 关联项目；NULL = 未关联（保持旧行为：仅存库） |
| `file_path` | NULL | 相对项目根的路径，如 `doc/登录需求.md` |
| `branch` | NULL | 实际使用的分支名，如 `v1.0` |

沿用既有迁移写法（`PRAGMA table_info` 检测缺列后 `ALTER TABLE`），老库无感。

## 3. git 操作（`src/main/git.ts`）

全部通过 `spawn('git', [...], { shell: false })` 调用，**不经 shell**（避免路径含空格/特殊字符出问题），统一带超时。

| 函数 | 作用 |
| --- | --- |
| `cloneRepo(url, dest)` | `git clone`，用于 R3 |
| `isGitRepo(path)` | `git rev-parse --is-inside-work-tree` |
| `currentBranch(path)` | `git rev-parse --abbrev-ref HEAD` |
| `listBranches(path)` | 本地分支列表 |
| `isClean(path)` | `git status --porcelain` 输出为空 |
| `ensureBranch(path, branch)` | 已存在→`checkout`；不存在→`checkout -b` |

### 必须注意的三个坑

**1. 私有仓库会永久挂起。** 没有终端时 git 会一直等凭据输入。所有 git 命令必须带：

```
GIT_TERMINAL_PROMPT=0        # 不弹凭据提示，直接失败
GCM_INTERACTIVE=never        # 关闭 Git Credential Manager 交互
```

否则用户填一个私有仓库地址，界面会卡死。

**2. 仓库可能没有提交。** 空仓库（`git init` 后无 commit）下 `checkout -b` 会因为无 HEAD 而失败。需检测并给出明确提示，而不是抛原始错误。

**3. detached HEAD / 分支名冲突。** `checkout` 同名但已被占用时要能分辨「切成功」与「切失败」，失败时把 git 的原始 stderr 透给用户。

## 4. 文档落盘与同步

**文件路径**：`<project>/doc/<标题净化>.md`。标题里 Windows 非法字符 `\ / : * ? " < > |` 替换为 `-`，限制长度；重名时追加序号。

**同步策略（避免双份数据打架）**：

- `creations.content`（DB）是**工作副本**，自动保存写它
- **同一次保存里也写文件**，让 `doc/` 下的文件始终跟得上
- 打开文档时：若 DB 内容为空但文件有内容 → **从文件导入**（覆盖「clone 下来的仓库里本来就有这份文档」的情形）
- 不做「文件被外部修改后自动回灌」（超出本轮范围，写入已知事项）

## 5. 润色

`polishDocument(content, cwd?)` 增加可选工作目录：

```
spawn(bin, ['-p', '--tools', '', '--append-system-prompt', SYSTEM_PROMPT], { cwd: projectPath })
```

- 有项目 → `cwd` 设为项目根，Claude Code 能读到该项目的 `CLAUDE.md` / 目录结构等上下文
- 无项目 → 保持原行为（用应用默认 cwd）
- **`--tools ""` 不变**：能读上下文，不碰文件。这是需求确认时选定的权限档位

## 6. 界面

`CreateDialog` 增加「项目」区：

```
新增创作
├── 项目
│   ├── [选择已有 ▾]  ← 用过的项目列表（来自 projects 表）
│   ├── ( ) git 地址  [https://...        ]
│   └── ( ) 本地项目  [路径] [浏览…]
├── 版本号  [1.0        ]  → 提示：将使用分支 v1.0
└── 需求标题 [          ]
```

- 选已有项目时，隐藏新建区，直接复用
- 提交时：解析项目（clone / 校验路径）→ 确保分支 → 建创作 → 写 `doc/` 文件 → 进编辑器

**进度反馈**：clone 可能耗时较久，弹窗内需显示阶段文字（`正在 clone…` / `正在切换分支…` / `正在写入文档…`），否则界面像卡死。

编辑器顶栏显示当前项目与分支，便于确认位置。

## 7. 测试计划

| 层 | 内容 |
| --- | --- |
| L6 git 逻辑 | 用**真实临时仓库**跑：建仓、commit、确保分支（新建/已存在切换）、脏工作区拒绝、空仓库报错、分支名生成 |
| L1~L5 | 既有 142 项全部保持通过（不能回归） |

git 层必须用真仓库测，不能只 mock——分支切换的边界情况（无 commit、脏工作区、分支已存在）正是容易出错的地方。

## 9. 明确不做

- 不做 git commit / push（只创建或切换分支、写文件；提交由用户自己决定）
- 不做 merge / rebase / 冲突处理
- 不做文件被外部修改后的自动回灌
- 不做多项目并行 clone 的进度条（只显示阶段文字）
