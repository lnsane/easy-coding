# easyCode v0.3.0

> 「协作」页新增「新增创作」→ 版本号/需求标题弹窗 → markdown 文档编辑窗口（左右分栏实时预览 + 工具栏）。
> 日期：2026-09-26

开发方案见 [`v0.3.0-dev.md`](v0.3.0-dev.md)，本文记录最终落地结果与验证情况。

## 需求

协作页面新增「新增创作」按钮 → 弹窗输入/选择版本号 + 输入需求标题 → 确定后进入 markdown 文档编辑窗口，支持实时编辑，顶部有 markdown 工具栏（加粗、标题、插入表格、插入超链接等）。

两个已确认的设计决策：

- **版本号 = 创作独立版本**（如 `1.0`、`1.1`），与 app 版本号无关；首次手填，之后从已用过的版本里选
- **编辑器布局 = 左右分栏**：左 markdown 源码，右实时预览

## 数据层

新增表 `creations`（在既有 `~/.easyCode/config.db` 内，复用同一连接）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | uuid |
| `version` | TEXT | 创作版本号 |
| `title` | TEXT | 需求标题 |
| `content` | TEXT DEFAULT '' | markdown 正文 |
| `created_at` / `updated_at` | INTEGER | 时间戳 |

两个索引：`version`（版本号聚合）、`updated_at DESC`（列表排序）。

**同一版本号允许建多条**（版本号是分类标签不是主键）。用 `CREATE TABLE IF NOT EXISTS` 建表，老库无感，无需 ALTER 迁移。

新增 IPC `creation:list / get / create / update / delete / versions`，经 `preload` 暴露为 `window.api.*`。

## 关键设计：变换逻辑抽成纯函数

工具栏每个动作本质是「文本 + 选区 → 新文本 + 新选区」。这类逻辑若直接写在 CodeMirror 回调里，就只能靠手点界面验证，**无法自动化测试**。

因此全部抽到 `src/renderer/src/lib/markdown-actions.ts`：纯函数、不 import CodeMirror、不碰 DOM，可用 node 直接跑断言。编辑器侧只做薄封装。

这正是「反复测试和代码逻辑验证」能落地的前提——最终该文件有 **76 项断言**覆盖。

编辑器写回时用 `diffRange()` 求**最小变化区间**再 dispatch，而不是整篇替换：整篇替换会把撤销合并成一大步、且光标映射会错乱。

## 界面

```
MainPage（协作 tab）
├── 列表态 CreationList：「+ 新增创作」按钮 + 创作卡片（版本号徽标/标题/摘要/更新时间），可删除（二次确认）
└── 编辑态 DocEditor
      ├── 顶栏：← 返回 ｜ v版本号 徽标 ｜ 可编辑标题 ｜ 保存状态
      ├── MarkdownToolbar
      └── 左 CodeMirror（markdown）｜ 右 实时预览（marked + DOMPurify）
```

### 工具栏

加粗 / 斜体 / 删除线 / 行内代码 ｜ H1 / H2 / H3 ｜ 无序列表 / 有序列表 / 引用 ｜ 表格 / 链接 / 图片 / 分割线 / 代码块 ｜ 撤销 / 重做

- 工具栏按钮用 `onMouseDown` + `preventDefault`：否则点按钮会让编辑器失焦、选区丢失，插入类动作就作用不到原位置
- 加粗/斜体/删除线/行内代码 与 标题/列表/引用 均为**开关**：已应用状态下再点即取消
- 标题、列表、引用先把**选区扩展到整行**，避免产生「半行加前缀」的坏文档

### 自动保存

编辑器不做自动保存就等于「关窗即丢」，实际使用中就是 bug。因此：

- 正文/标题变更后 **800ms 防抖**落库
- 返回列表、组件卸载、切文档时**立即 flush**，防抖窗口内的最后一次输入不会丢
- 顶栏显示 `未修改 / 保存中… / 已保存 / 保存失败`
- 用递增序号做竞态防护，旧请求回来不会覆盖新状态
- `updateCreation` 只刷新列表数据，**不重载正在编辑的文档内容**，否则每次自动保存都会把用户正在输入的编辑器内容顶掉

### 安全

预览走 `dangerouslySetInnerHTML`，因此渲染链路强制过 DOMPurify：`marked.parse()` → `DOMPurify.sanitize()` → `innerHTML`。已用 20 项断言验证 script / onerror / javascript: / iframe / svg onload 等均被拦截。

CSP 无需放宽：CodeMirror 6 靠注入 `<style>`，现有 `style-src 'self' 'unsafe-inline'` 已覆盖。

## 开发过程中修掉的自身 bug

纯函数测试的价值在开发中直接体现——以下问题都是**测试跑出来的**，不是靠肉眼看出来的：

| 问题 | 现象 | 修法 |
| --- | --- | --- |
| 光标不跟随前缀 | `\|abc` 点 H1 后光标停在 `#` **前**面 | 光标偏移改为以「前缀之后的正文」为原点，保证往返一致 |
| 光标在标记内点加粗无效 | `**b\|c**` 点加粗会又插一对 `**` | 增加「同一行内查找包住光标的标记对」分支 |
| 前缀长度反推错误 | 切换前缀款式（`1. `→`- `）时算出**负数**偏移，选区越界 | 改为记录每行**实际**增删的前缀长度，而非事后用正则反推 |
| 空文档点标题无反应 | 空行被判定为「无可操作对象」 | 空文档/空行仍插入前缀并把光标放到前缀后 |

- 编辑区与预览区各自独立滚动
- 未做 markdown 文件导入/导出、多文档 diff、协同编辑（见 dev 文档第 9 节）

- 打包体积：renderer 产物由 665KB 增至约 1.98MB（CodeMirror + marked + DOMPurify）。后续若要压体积，可对预览做动态 import
