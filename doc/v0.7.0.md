# easyCode v0.7.0

> 润色改为**直写模式**：关联项目时让 Claude Code 直接改写项目里的文档，配 `--dangerously-skip-permissions`。
> 日期：2026-09-27

## ⚠️ 这一版推翻了先前的一条约定

v0.4.0 确认过的决策是「润色**只能润色、不能改变文件**」，v0.6.0 更把工具全禁（`--tools ""`）。

本版本按要求改为**允许它直接写文件**。这是能力放宽，不是等价替换：

| | v0.6.0 | v0.7.0 |
| --- | --- | --- |
| 工具 | `--tools ""`（零工具） | 关联项目时 `--tools "Read,Write,Edit"` |
| 能否改磁盘 | **不能**（连读都不行） | **能改指定的那个文件** |
| 是否需逐处确认 | 需要 | 结果写回文件后，仍弹确认框对照 |

保留的边界：**不含 Bash**，因此它无法执行任何命令（不能装依赖、删文件、外发请求）。

## 变更内容

### 两种模式

**A. 直写模式**（关联了项目、且文档有落盘路径）

```
claude -p --tools "Read,Write,Edit" --dangerously-skip-permissions --append-system-prompt <规则>
```

让它读取 `doc/xxx.md`、润色后用 `Edit` 写回同一个文件。

**B. 只读模式**（未关联项目）：`--tools ""` + stdin 管道，与 v0.6.0 一致。它碰不到磁盘。

### `--dangerously-skip-permissions` 的作用（实测澄清）

对这个参数的理解经过了一次修正，过程值得记下来：

- **初判**：它是「跳过权限检查」，属于放宽权限，与「让润色质量变好」无关 —— 这个判断是对的，实测加与不加的润色**结果完全一致**。
- **但漏了一点**：在「让它直接写文件」这件事上，它是**必需的**。实测对照：

| 命令 | 文件是否被改写 |
| --- | --- |
| `--tools "Read,Write,Edit"` + `--dangerously-skip-permissions` | ✅ 改成功 |
| `--tools "Read,Write,Edit"`（不加） | ❌ 改不动 |

原因：工具调用需要批准，而 headless 场景没有界面可以批准，于是被自动拒绝。所以 `--dangerously-skip-permissions` 在这里不是「图省事的开关」，而是**让直写生效的必要条件**。

### 渲染层适配

直写模式下 stdout 只有一句摘要，真正的结果在文件里。因此渲染层改为**重新读回文件**，用「改动前 vs 改动后」喂给确认弹窗；若文件与原文一致，则提示「文档无需修改」而不弹框。

### 安全性说明（诚实版）

`--tools "Read,Write,Edit"` 里的 `Write`/`Edit` 是**通用文件写工具，不限定路径**。因此严格来说，它在能力上可以改写项目里**任何**文件。

当前把范围收窄的手段是**系统提示中的指令约束**（「只处理用户指定的那一个文件」），而非技术强制。测试中用一个哨兵文件验证了它确实没有越界，但这属于「模型遵守了指令」，不是「技术上做不到」。

若要变成技术强制，需要把项目路径之外的写入在 `canUseTool` 回调里拒绝（Agent SDK 支持），或改用只允许单文件路径的方案。**当前未做**，作为已知事项记录。

## 验证

新增 L14（`test-polish-direct.mjs`，9 项）：

- 直写模式确实能改到目标文件（登陆→登录、在次→再次，结构保留）
- 工具集合恰好只含 `Read`/`Write`/`Edit`，**无 Bash、无 PowerShell**
- 哨兵文件未被越界改动
- **回归证据**：不加 `--dangerously-skip-permissions` 时文件改不动

同时更新 L11（`test-polish-filemode.mjs`）的说明，明确它现在守的是**未关联项目时的只读路径**，不再声称覆盖所有润色场景。

**十三层合计 341 项断言全部通过。**

## 已知事项

- **`Write`/`Edit` 不限定路径**：范围靠系统提示约束，非技术强制（见上）
- 润色质量由**提示词与模型**决定；本次改动只影响「能不能直接写回文件」
- 本机 Claude Code 被路由到国产模型（`ANTHROPIC_BASE_URL=http://127.0.0.1:3199`），若润色质量不满意，可先用 `--settings` 换模型（实测该参数能覆盖 `settings.json`）
- 「执行编排任务」功能不受本次改动影响
