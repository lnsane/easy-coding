# easyCode v0.8.1

> 修「生成开发计划」的超时问题：阈值从 8 分钟提到 **5 小时**，并把 claude 调用的进程终止逻辑抽成共享模块（此前 `polish.ts` 与 `plan.ts` 都在用会留孤儿的 `child.kill()`）。
> 日期：2026-09-27

## 现象

生成开发计划时，跑到 480 秒被中止。日志：

```
23:05:17  信息  只读检索模式：工具白名单 Read,Glob,Grep（无 Write / Edit / Bash…）
23:05:18  警告  [claude-code:unrecognized_model] {…}
23:13:17  警告  超时中止（480.0s）
23:13:17  警告  退出码 null（耗时 480.1s）
```

三个问题：

1. **8 分钟不够** —— 只读检索模式要读较多文件，当时它仍在正常工作
2. **日志重复** —— 「超时中止」之后又打一条「退出码 null」，像失败了两次
3. **超时中止用的是 `child.kill()`** —— 会让 `claude.exe` 变成孤儿继续跑

## 修复

### 1. 超时阈值 8 分钟 → 5 小时

本机 Claude Code 被路由到国产模型（`cline-pass/deepseek-v4.1-flash`），速度比官方模型慢不少。计划生成是「读代码 + 产出长文档」，耗时天然比润色长，阈值需要留足余量。

### 2. 修掉重复日志

`child.on('close')` 没有检查 `settled`。`killTree` 之后 close 仍会触发，于是超时分支已经报告过失败，close 分支又报一次「退出码 null」。

修法：close 处理器开头 `if (settled) return`。`polish.ts` 有同样的问题，一并修掉。

### 3. 抽出共享的 `killTree`

**这是本轮最值得记的一条。** `plan.ts` 用的是：

```js
try { child.kill() } catch {}
```

而 `child.kill()` **只杀直接子进程**，`claude.exe` 会变成孤儿继续跑（继续消耗 token）——**这个坑我在编排功能里已经实测踩过一次**，当时把正确实现（`taskkill /F /T`）写在了 `orchestrate.ts` **内部**，没有抽取复用。结果 `polish.ts` 与 `plan.ts` 又各自犯了一次。

新增 `src/main/kill-tree.ts`，三处共用：

```ts
killTree(pid, detached?)
```

- Windows：`taskkill /F /T /PID`（杀整棵树）
- POSIX：`detached` 时用负 PID 杀进程组，否则退化为单进程 `SIGKILL`
- 对 `undefined` / 已退出的 PID 均不抛错（可安全重复调用）

> **教训**：修好一个坑之后，**要把修复放进共享位置**，而不是留在发现它的那个文件里。否则下一个用到同类逻辑的地方必然重犯。这和 v0.8.0 记过的「测试不得复制实现的 prompt」是同一类问题——复制出来的那份一定会漂移。

## 验证

新增 L16（`test-kill-tree.mjs`，4 项）：

- 对 `undefined` / `0` 不抛错
- 对已退出的 PID 不抛错，且可重复调用
- **真起一个 `claude` 长任务 → `killTree` → 进程表比对：无孤儿残留**
- POSIX 分支单独覆盖

**十五层合计 352 项断言全部通过。**

### 一次尝试后撤回的改动

顺手改 `git.ts` 时，把它超时路径的 `child.kill()` 也换成了共享 `killTree`（为了统一）。结果 **`test-git.mjs` 与 `test-e2e-flow.mjs` 直接崩溃**，报 libuv 断言失败：

```
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING), file src\win\async.c, line 94
```

根因：这两个测试**用纯 Node 直接跑 `.ts`**，而源文件之间用的是**不带扩展名**的 import（`from './kill-tree'`，由打包器解析）。`git.ts` 此前**没有任何内部 import**，我加的这行是第一个，于是第一次暴露了这个差异。

试过带扩展名 `'./kill-tree.ts'`：Node 能解析了，但 `tsc` 报 TS5097（需要开 `allowImportingTsExtensions`）。为一个非必要的改动去改全项目编译配置，不划算。

**最终决定撤回**，`git.ts` 仍用 `child.kill()`，并在注释里写明原因：

- git 是**单进程**，超时路径原本工作正常
- 它的交互式助手（凭据管理器 / pager）已由 `gitEnv()` 的 `GIT_TERMINAL_PROMPT=0` 与 `GCM_INTERACTIVE=never` 禁掉
- 为「一致性」引入真实破坏不划算

> **这条记下来的价值**：「统一成共享实现」不是无条件的。当一个地方本来没问题、而统一会带来实测可见的破坏时，正确的做法是**保留差异并写明原因**，而不是硬统一。

## 已知事项

- 5 小时仍是上限，不是预期耗时。阈值定得宽是有意的：宁可用户自己关面板，也不要中途把还在干的活掐掉
- 计划生成期间可以关闭过程面板，但不影响后台执行；目前**没有「中止」按钮**（润色也没有，只有「执行编排任务」有）。如需中止计划生成，可后续补上，`killTree` 已就绪
