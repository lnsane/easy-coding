# easyCode v0.4.1

> 润色功能改进：执行过程可见、改为「让 Claude Code 读文件」的方式、提示词从「仅语言」改为「结构化补充」。并给出「执行编排任务」功能的开发文档。
> 日期：2026-09-26

## 变更背景

v0.4.0 的润色有三个问题：

1. **看不见执行过程** —— 点一下只有转圈，等 30~60 秒毫无反馈，像卡死或没反应
2. **调用方式间接** —— 把正文塞进 stdin，Claude Code 拿到的是一段孤立文本，看不到项目结构
3. **润色结果不够详细** —— 用户反馈「感觉润色的文档不够详细」

## 本版本变更

### 1. 执行过程可见

新增 `PolishProgress` 面板，从底部弹出，实时显示（主进程通过 `polish:log` 频道推送，非结束后一次性返回）：

```
工作目录：C:\Users\wangc\Desktop\easyCode     ← 单独高亮
22:36:58  信息   已找到 Claude Code：...\claude.exe
22:36:58  信息   该项目没有 CLAUDE.md
22:36:58  信息   文件模式：让 Claude Code 自己读取 doc/xxx.md
22:36:58  命令   claude -p --tools Read --append-system-prompt <润色规则>
22:37:32  完成   完成，返回 141 字符，耗时 34.8s
```

每轮用独立 `runId` 隔离，上一次的日志不会串到这一次。

### 2. 改为「文件模式」

关联项目时，不再把正文塞进 stdin，而是**把文档路径告诉 Claude Code，让它自己读**：

```diff
- claude -p --tools ""        # 正文走 stdin
+ claude -p --tools Read      # 让它自己读 doc/xxx.md，cwd = 项目根
```

好处是它能按**真实项目结构**读文件，并吃到项目的 `CLAUDE.md` 上下文。

**权限仍然收紧**：只授予 `Read`，**不授予任何写工具**。已用**对抗测试**证明：
即使明确命令它「用 Write 工具把内容写回文件覆盖它」，磁盘文件**哈希仍完全一致**。

未关联项目时退回文本模式（`--tools ""`），完全不授予工具。

### 3. 提示词改为「结构化补充」

用户最初选的是「仅语言润色」，那条规则明确写了「不增删内容」—— 这**正是**「不够详细」的原因：140 字进、141 字出是遵守规则的正确行为，而非 bug。

经确认改为「需求草稿 → 可开发的需求文档」，实测同一份 140 字草稿：

| | 旧规则 | 新规则 |
| --- | --- | --- |
| 字数 | 140 → **141** | 140 → **约 700** |
| 结构 | 3 段散文 | 背景与目标 / 功能点 / 交互流程 / 待明确事项 / 验收标准 |

新规则的关键约束：

- **不要编造需求** —— 原文没提到的功能不发明，而是把「开发时必须明确但原文没写」的列成**待明确事项**（是提问，不是替用户拍板）
- 补全只针对「原文已暗示、开发时必须明确」的细节
- 不确定处宁可保留原文的模糊说法

风险由既有确认弹窗兜底：结果先不落盘，用户逐处勾选接受或撤回。

### 4. 新增「执行编排任务」开发文档

`doc/v0.5.0-dev.md` —— 对应 `doc/markdwon的润色测试.md` 那份需求。含数据模型（`roles` / `runs` 表）、执行流程、安全设计与测试计划。**尚未实现**，仅文档。

## 验证

新增两层，**十层合计 294 项断言全部通过**：

| 层 | 项数 | 覆盖 |
| --- | --- | --- |
| L10 润色 cwd | 12 | **用 `CLAUDE.md` 对照实验证明 cwd 生效**：projA 答 ZEBRA-42、projB 答 PANDA-99、交叉不含。另用哨兵文件验证禁用工具后内容不泄露 |
| L11 润色文件模式 | 10 | 按路径读取成功、**磁盘哈希不变**、被命令写文件仍改不动、CLAUDE.md 术语约定被遵守 |

### 关于 cwd 的验证方法

「传了 cwd 参数」不等于「cwd 生效」，所以用**能证伪的实验**：在不同项目目录放不同代号的 `CLAUDE.md`，看模型答出哪个。这验证的是子进程真的读到了那个目录下的内容。

## 已知事项

- 那行 `[claude-code:unrecognized_model]` 警告是**本机 Claude Code 被路由到国产模型**所致，非错误：
  `~/.claude/settings.json` 里 `ANTHROPIC_BASE_URL=http://127.0.0.1:3199`（本机 ccr 代理），
  `ANTHROPIC_MODEL=cline-pass/deepseek-v4.1-flash`。即「跑的是 Claude Code，背后模型是 DeepSeek」。
- 实测 `--settings` 参数**可以覆盖** `settings.json`（环境变量不行，会被 settings.json 盖掉），
  因此后续可加「润色用哪个模型」的选择（如 `glm-5.3` / `kimi-k3`）。
- 「执行编排任务」仅有开发文档，功能未实现
