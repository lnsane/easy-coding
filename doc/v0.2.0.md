# easyCode v0.2.0

> 接入 GitHub Actions 多平台打包 CI，修复 renderer 侧一处模块路径错误，并首次把全部源码纳入版本控制。
> 日期：2026-09-26

## 变更背景

此前打包完全依赖本机双击 `打包.bat`，只能在 Windows 上出包，且出现过一次并发打包互相覆盖、产出 189KB 空壳安装包的事故（载荷未嵌入，装不了）。同时仓库只有一次 `Initial commit`，仅含 LICENSE 与 README，全部源码都还没进 git。

本版本补齐「代码入库 + 云端多平台出包」这条链路。

## 本版本变更

### 1. 首次将全部源码纳入版本控制

`Initial commit` 只提交了 LICENSE 与 README，`src/`、配置文件全在工作区未跟踪状态。本版本一并入库。

顺带清理与调整：

| 文件 | 处理 |
| --- | --- |
| `_test_a.bat` / `_test_b.bat` / `_test_c.bat` | **删除**。这是排查"electron-builder 是否会重写 `.npmrc` 中的 `electron_mirror`"时留下的三个环境变量变体，结论已得出，无保留价值 |
| `.npmrc` | **加入 `.gitignore`**。内容是国内镜像（`electron_mirror=https://npmmirror.com/mirrors/electron/`），只对当前网络环境有效；提交上去会让境外 CI runner 也走国内镜像，反而变慢甚至超时 |
| `package.json` | 补充 `author` 字段（electron-builder 打包 Linux deb 时要求） |

### 2. 修复 `store.ts` 模块路径错误

`src/renderer/src/store.ts` 中：

```diff
- import type { AIConfig, AIConfigInput } from '../../../shared/types'
+ import type { AIConfig, AIConfigInput } from '../../shared/types'
```

该文件位于 `src/renderer/src/`，三级 `../../../` 会解析到仓库根目录的 `shared/types`（不存在），应为两级 `../../shared/types`。同目录下的 `components/*.tsx` 用三级是正确的——它们深一层。

此错误此前被掩盖：`electron-vite` 走 esbuild，只转译不做类型检查，`import type` 又被完全擦除，因此运行时无感。现新增 `npm run typecheck`（`tsc --noEmit`）将其暴露，并纳入 CI 前置步骤。

### 3. 新增 GitHub Actions 多平台打包 CI

新增 `.github/workflows/build.yml`。触发条件：push 到 `main`、指向 `main` 的 PR、手动 `workflow_dispatch`、推送 `v*` tag。

三个平台并行（`fail-fast: false`，单个平台失败不阻塞其他平台）：

| Runner | `electron-builder` 参数 | 产物 |
| --- | --- | --- |
| `windows-latest` | `--win --x64` | NSIS 安装包 `.exe`、免安装 `.zip` |
| `ubuntu-latest` | `--linux --x64` | `x86_64.AppImage`、`.deb` |
| `macos-latest` | `--mac --x64 --arm64` | `.dmg`、`.zip`（两种架构） |

步骤：`npm ci` → `npm run typecheck` → `npm run build` → `electron-builder` → 上传 artifact。

两处关键设计：

- **安装包体积下限校验（仅 Windows）**：产物小于 20MB 直接判失败。正常安装包约 92MB，空壳只有不到 1MB，这道卡口让历史上的空壳事故一眼可见，而不是发出一个装不上的包。
- **artifact 的 `if-no-files-found: error`**：没有产物即视为打包静默失败，不让 job 假绿。

发版路径：推送 `v*` tag 后，`release` job 汇总三平台产物，创建 GitHub Release 并附上自动生成的 release notes。日常 push 则只在 workflow run 的 Artifacts 区留下产物（保留 14 天）。

### 4. 打包配置补充 macOS / Linux 目标

`package.json` 的 `build` 字段原本只有 `win`，补上 `mac`（`dmg` + `zip`）与 `linux`（`AppImage` + `deb`）块，CI 才能在这些平台出包。

> **macOS 签名**：当前无 Apple 开发者证书，产物是未签名的。用户首次打开会被 Gatekeeper 拦截，需右键「打开」或在「系统设置 → 隐私与安全性」中放行。若后续需要公证，需配置 `CSC_LINK` / `CSC_KEY_PASSWORD` 等 secrets。
