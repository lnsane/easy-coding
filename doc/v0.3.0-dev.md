# easyCode 「协作 · 新增创作」开发文档

> 版本：v0.3.0 ｜ 日期：2026-09-26
> 需求方原话：协作页面要新增一个按钮叫「新增创作」，点击弹出的窗口要输入版本号或者选择版本号，然后输入需求标题，点击确定后到了协作的页面，是一种文档编辑窗口，是 markdown 文档的格式，要支持 markdown 实时编辑，并且上面有 markdown 工具栏（字体加粗、设置标题、插入表格、插入超链接等等）。要求功能完整无 bug，反复测试和代码逻辑验证。

## 1. 需求拆解

| # | 需求点 | 落地方式 |
| --- | --- | --- |
| R1 | 「协作」页新增「新增创作」按钮 | 协作 tab 的列表态顶部按钮 |
| R2 | 点击弹出窗口 | 模态弹窗 `CreateDialog` |
| R3 | 弹窗内输入**或选择**版本号 | `<input list>` + `<datalist>`：原生同时支持自由输入与下拉选择 |
| R4 | 弹窗内输入需求标题 | 文本输入，必填 |
| R5 | 点确定后进入文档编辑窗口 | 协作 tab 切到编辑态，渲染 `DocEditor` |
| R6 | markdown 格式，支持实时编辑 | CodeMirror 6（markdown 语法）+ 右侧实时预览 |
| R7 | 顶部 markdown 工具栏 | 加粗/斜体/删除线/标题/列表/引用/代码/表格/链接/图片/分割线/撤销重做 |

### 已确认的两个决策

1. **版本号语义**：**创作独立版本**，与 app 版本号无关（如 `1.0`、`1.1`）。首次手填，之后下拉列出已用过的版本号供选。
2. **编辑器布局**：**左右分栏实时预览** —— 左 markdown 源码，右渲染结果。

## 2. 数据模型

新增表 `creations`（存于既有 `~/.easyCode/config.db`，复用同一连接）：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PRIMARY KEY | uuid |
| `version` | TEXT NOT NULL | 创作版本号，自由文本如 `1.0` |
| `title` | TEXT NOT NULL | 需求标题 |
| `content` | TEXT NOT NULL DEFAULT '' | markdown 正文 |
| `created_at` | INTEGER NOT NULL | 创建时间戳 |
| `updated_at` | INTEGER NOT NULL | 最后修改时间戳 |

索引：`CREATE INDEX idx_creations_version ON creations(version)`（下拉版本号列表要按 version 聚合）。

**迁移**：`CREATE TABLE IF NOT EXISTS`，无需 ALTER。与既有 `migrate()` 并列执行，老库无感。

**同一版本号可建多条创作**：版本号是分类标签不是主键，不唯一约束（用户可能为 `1.0` 建「登录需求」「支付需求」两条）。

## 3. 接口设计

### 共享类型（`src/shared/types.ts`）

```ts
export interface Creation {
  id: string
  version: string
  title: string
  content: string
  createdAt: number
  updatedAt: number
}

/** 新建时提交 */
export interface CreationInput {
  version: string
  title: string
}

/** 更新正文/标题 */
export interface CreationUpdate {
  title?: string
  content?: string
}
```

### IPC（`creation:*`）

| 频道 | 入参 | 返回 | 说明 |
| --- | --- | --- | --- |
| `creation:list` | — | `Creation[]` | 按 `updated_at DESC` |
| `creation:get` | `id` | `Creation \| null` | |
| `creation:create` | `CreationInput` | `Creation` | 正文初始化为空 |
| `creation:update` | `id, CreationUpdate` | `Creation` | 局部更新，刷新 `updated_at` |
| `creation:delete` | `id` | `void` | |
| `creation:versions` | — | `string[]` | 已用过的版本号，去重，按首次使用时间 |

`preload` 同步暴露到 `window.api`，`env.d.ts` 经 `EasyCodeApi` 自动获得类型（无需改动）。

## 4. 关键设计：把变换逻辑做成纯函数

**这是保证「无 bug」的核心决策。**

工具栏每个动作（加粗、设标题、插表格…）本质是「一段文本 + 选区 → 新文本 + 新选区」。如果直接把逻辑写在 CodeMirror 的 dispatch 回调里，就只能靠手点界面来验证，无法自动化测试。

因此把全部变换逻辑抽到 `src/renderer/src/lib/markdown-actions.ts`，签名为：

```ts
export interface EditResult {
  text: string
  selectionStart: number
  selectionEnd: number
}
type Action = (text: string, start: number, end: number) => EditResult
```

- **纯函数、零依赖**（不 import CodeMirror、不碰 DOM）→ 可用 node 直接跑断言测试
- CodeMirror 侧只做薄封装：读出 `state.doc.toString()` 与选区 → 调纯函数 → 把结果 dispatch 回编辑器

这样「反复测试和代码逻辑验证」就有了实际的抓手，而不是只能靠肉眼。

### 各动作行为规格

| 动作 | 无选中时 | 有选中时 | 再次点击（已应用） |
| --- | --- | --- | --- |
| 加粗 | 插入 `****`，光标居中 | 包裹 `**sel**` | 识别已加粗 → 取消包裹 |
| 斜体 | 插入 `**`，光标居中 | 包裹 `*sel*` | 同上，取消 |
| 删除线 | 插入 `~~~~`，光标居中 | 包裹 `~~sel~~` | 同上，取消 |
| 行内代码 | 插入 ` `` `，光标居中 | 包裹 `` `sel` `` | 同上，取消 |
| 标题 H1/H2/H3 | 当前行加 `# ` 前缀 | 同左（按行处理） | 同前缀 → 去除（切回正文） |
| 无序列表 | 当前行加 `- ` | 每行加 `- ` | 已有 → 整体去除 |
| 有序列表 | 当前行加 `1. ` 起 | 逐行 `1. ` `2. `… | 已有 → 整体去除 |
| 引用 | 当前行加 `> ` | 每行加 `> ` | 已有 → 整体去除 |
| 代码块 | 插入三反引号围栏，光标在中间 | 用围栏包裹选中 | — |
| 表格 | 插入 2×3 空表模板 | 同左（忽略选区） | — |
| 超链接 | 插入 `[链接文字](url)`，选中「链接文字」 | `[sel](url)`，选中 `url` | — |
| 图片 | 插入 `![图片描述](url)` | 同左 | — |
| 分割线 | 当前行下方插入 `---` | 同左 | — |
| 撤销/重做 | 走 CodeMirror 内建 history | | |

**多行包裹的边界情况**：标题、列表、引用这类「按行加前缀」的动作，若选区从行中间开始，需**扩展到整行边界**再处理，否则会产生半行加前缀的坏文档。这是最容易出 bug 的地方，规格里显式约定并测试。

**有序列表的编号**：逐行递增，且要能识别已有行的编号并重排（选中 3 行已有 `1.` 的列表点有序列表 → 变成 `1. 2. 3.`）。

## 5. UI 结构

```
MainPage（协作 tab）
├── 列表态：CreationList
│     ├── 顶部：「新增创作」按钮
│     └── 创作卡片列表（版本号徽标 + 标题 + 更新时间），点击进入编辑态
│           每项可删除（二次确认）
└── 编辑态：DocEditor
      ├── 顶栏：← 返回 ｜ 版本号 · 标题（可改）｜ 保存状态
      ├── MarkdownToolbar（按钮组，带分隔）
      └── 主体：左 CodeMirror（markdown）｜ 右 实时预览（marked + DOMPurify）
```

### 状态归属

- `MainPage` 持有 `activeCreationId`，`null` = 列表态。切 tab 不清空（返回协作页仍停在原文档）。
- `store.ts` 增加创作相关：`creations`、`versions`、`loading`，以及 `createCreation` / `updateCreation` / `deleteCreation` / `loadCreations`。

### 自动保存

文档编辑器若无自动保存，关窗即丢内容 —— 这在实际使用中就是 bug。设计：

- 编辑正文后 **800ms 防抖**写入 DB，写前 `flush` 前一次的挂起写入
- 返回列表 / 组件卸载 / 切 tab 时**立即 flush**，避免最后一次输入丢失
- 顶栏显示状态：`保存中…` / `已保存` / `保存失败`
- 竞态防护：用递增的序号（或比较写入内容）确保「旧请求覆盖新内容」不会发生

## 6. 依赖选型

| 包 | 用途 | 理由 |
| --- | --- | --- |
| `@uiw/react-codemirror` + `@codemirror/lang-markdown` | markdown 源码编辑 | 成熟、受控、能拿到 EditorView 做工具栏变换 |
| `marked` | markdown → HTML | 轻量、同步 API，适合实时预览 |
| `dompurify` | 渲染结果消毒 | **必需**：预览是 `dangerouslySetInnerHTML`，不消毒等于开了 XSS 口子 |

预览渲染链路：`content` → `marked.parse()` → `DOMPurify.sanitize()` → `innerHTML`。

> **CSP 注意**：`index.html` 现有 CSP 为 `script-src 'self'; style-src 'self' 'unsafe-inline'`。CodeMirror 6 通过注入 `<style>` 工作，`'unsafe-inline'` 已覆盖；预览不执行脚本，`script-src 'self'` 不影响。**无需放宽 CSP**。

## 7. 测试计划

「功能完整并无 bug」的要求下，验证分三层：

### L1 纯函数单测（自动化，覆盖变换逻辑）
对 `markdown-actions.ts` 的每个动作，用 node 跑断言，覆盖矩阵：

- 无选中 / 行内选中 / 跨行选中 / 选区从行中间开始
- 已应用状态下的再次点击（取消）
- 多行列表编号重排
- 边界：空文档、光标在文首/文末、选区覆盖整个文档、末尾无换行

### L2 数据层验证（自动化）
用 `node:sqlite` 直接对表跑 CRUD：建表、插入、按更新时间排序、局部更新只改指定字段、版本号去重聚合、删除。

### L3 实机验证（手动 + 脚本）
编译 → 启动 → 逐项走查：新增创作弹窗（含 datalist 选择）、确定进编辑器、工具栏每个按钮的实际效果、预览同步、自动保存后重启应用内容还在。

## 9. 明确不做（避免范围蔓延）

- 不做 AI 生成正文（本轮只做文档编辑器本身）
